# MVP 验收矩阵

Q 独立审查；合成夹具不代表业务签收。执行后必须附提交与证据，不能仅勾选。M1 工程场景于 2026-09-06 通过，具体版本、执行方式与局限见 [M1 验收记录](verification/m1.md)；后续里程碑仍待验证。

## M1 必验

| ID | 场景 | 通过条件 | 证据方式 |
| --- | --- | --- | --- |
| M1-01 | 旧项目无production字段 | GET无写副作用、无自动迁移或批准 | 数据库前后比较 |
| M1-02 | 显式初始化两次 | 首次空底座，第二次无新增业务/内部版本，旧诊断对象不变 | HTTP＋数据库 |
| M1-03 | 升级前回执升级后重放 | 原响应完全一致，同键异参409，历史记录不变 | 真实命令回执 |
| M1-04 | 项目列表空/多项/未授权 | 排序稳定，能打开真实项目，无权限不泄露 | HTTP |
| M1-05 | SSE分块、心跳、多帧、续传 | 正确使用事件id，不用revision；重连只读，不重放POST | 流解析＋浏览器 |
| M1-06 | 同项目旧GET晚返回 | revision不回退，草稿不被服务器覆盖 | 控制响应顺序 |
| M1-07 | A流/GET迟于切到B返回 | A不能覆盖B，旧流关闭，迟到回调失效 | 浏览器 |
| M1-08 | 已提交但丢失响应 | pending持续阻止新写/切项目，GET与SSE不清pending，同key回放一次生效 | 真实HTTP故障注入 |
| M1-09 | 写入401后重连 | 保留原请求/草稿；更新凭据后明确重试，无自动模型调用 | 浏览器 |
| M1-10 | 写入409后复核 | 先读新版本再解除冲突；保留本地修改并明确提交 | 外部HTTP并发＋浏览器 |
| M1-11 | 草稿A→B→A | 内容隔离，依赖变化要求复核，保存A不删B | 浏览器 |
| M1-12 | 刷新/重开并重新认证 | token未持久化；恢复项目草稿但校验依赖 | 浏览器＋存储检查 |

现有 `frontend.integration.test.ts` 仅证明客户端HTTP调用；不能替代真实hook/浏览器对会话和草稿的验证。

## 后续里程碑的硬门

| 阶段 | 核心验证 |
| --- | --- |
| M2 | 原件定位、用途隔离、单文件失败不阻断整批、规则缺失不能创建正式目标 |
| M3 | Facts不可原地覆盖，未确认/参考/冲突不可用于正式输出；3/6/8章节稳定ID与绑定，正式批准由人工 |
| M4 | 同快照固定环境连续渲染3次一致；锁不被覆盖；缺图/字体失败/溢出不能静默通过；真实图片候选人工签收 |
| M5 | 本地化保留事实，确定性单位换算留原值和精度；市场覆盖不反写母版/其他市场 |
| M6 | 精确版本QA、文件完整性、Manifest版本及hash、幂等导出；未批准/stale/blocked/缺文件禁止正式下载 |
| 全链路 | 改动一条已使用事实仅使相关对象失效，无关内容/批准版本/渲染结果保持不变 |
| 运行恢复 | PostgreSQL真实并发、回执、迁移、Worker租约、重连；不是PGlite的替代性结论 |
