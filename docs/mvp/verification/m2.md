## 2C 真实浏览器证据

集成浏览器使用 1440×1000 Chromium、原 `/arcane-warrior`、真实 Fastify 和 PostgreSQL。隔离 schema 为本次 `mvp_browser_*`，两个应用共享此存储：4312 使用显式合成规则，4313 使用真实空目录；前端分别代理于 5182、5183。没有启动模型 Gateway。浏览器执行由主 Agent 完成，Q 独立核对最终代码、6 份脚本与 6 张截图。

| 场景 | 已观察行为 |
| --- | --- |
| 部分草稿与启用 | 仅填部分字段可保存，字段或规则缺失阻止启用；补齐后明确启用 P1 |
| 历史版本 | P1 只读，明确复制到新草稿、保存、启用 P2；P1 原快照逐字段保持不变，无正式 Facts／Section 自动生成 |
| 本地恢复 | A/B 草稿分别保留；重新打开页面需重新输入凭据；恢复旧草稿仍使用原起草依据，服务端已变时必须复核 |
| 空规则 | 完整上下文能保存为草稿；前端禁止启用；真实 API 返回 409 `RULE_PACK_UNAVAILABLE`，不增加版本或 revision |
| 旧回执晚到 | 真实保存已提交但暂缓回执，再执行较新配置变更，SSE 先更新页面；未决写仍锁住，旧回执到达后本地输入保留并要求复核 |
| 无关版本变化 | 较新的身份修改不改变当前配置含义；旧配置回执返回后允许正确清理已保存的本地草稿 |
| 同 revision 回读 | 等待 GET response、body 完成、刷新完成提示及 busy 清空后再断言；本地编辑保留，无 JSON 键顺序误报且能保存 |
| 页头与隔离 | 按已启用版本显示首发平台／站点／语言；只有服务端草稿显示“草稿未启用”，空配置显示“尚未配置”，项目切换同步更新 |
