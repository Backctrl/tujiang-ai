| 验收项 | 实际操作与结果 |
| --- | --- |
| 旧项目、列表与初始化 | 401 列表拒绝；合法列表按规则排序；旧项目 GET 前后数据库无写入；初始化两次不追加内部／业务版本；旧创建回执逐字段重放一致，同键异参返回 409 |
| 项目隔离和重开 | UI 新建 A／B，分别输入资料草稿，A→B→A 恢复正确；保存 A 后 B 草稿仍保留；重开后重新认证，token 不在持久草稿中 |
| 上游变化与草稿复核 | 离开 A 后外部请求修改 A 身份，再回 A，原草稿保留并显示旧／新依据；修改候选替换目标后仍要求复核，复核与放弃入口均可见 |
| 409 冲突 | 外部 HTTP 写入先推进版本；本地保存收到 409 后读取新版本，保留本地输入，明确复核后才能提交 |
| 未决写入 | 真实后端已提交但丢弃响应；SSE 先将页面推进到新 revision，pending 仍保留，新写和切换均禁用；显式重试使用完全相同的 key／body，只生效一次 |
| 401 凭据恢复 | 首次写入真实发送旧 token，后端返回 401；UI 输入新 token 后显式重试，捕获两次请求 body／key 一致、Authorization 确实变化，返回状态为 401→200 |
| SSE 断开与恢复 | 中断流后重连只读，不额外 POST；使用审计事件 ID 续传；分块、多帧和心跳由客户端解析测试覆盖 |
| 迟到与乱序 | 旧 GET 晚到不能倒退 revision；A 的迟到 GET／流回调不能覆盖 B；切换后旧订阅失效；旧保存结果不能把新的候选依赖绑定为已复核 |
